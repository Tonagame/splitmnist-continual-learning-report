# My takeaways from the project

For our python course final project, we were tasked to find and reproduce the results of a paper about tackling the problem of catastrophic forgetting (CF) in machine learning (ML) models. The paper we chose surveyed multiple methods to mitigate CF applied across 3 scenarios of continual learning (CL) - checking the ability of the model to learn and perform one task after another.

In our project, we decided to focus on a subset of methods from the paper and apply each one to the 3 CL scenarios - checking their performance and comparing to the paper's results. The code was mainly generated by ai (using OpenAI's Codex) under our instructions and planning - providing the paper and dataset, guiding it to implement each method we chose and fix any problems that came up.

The first stage (running the paper's code locally) was rather easy - the code had an intuitive interface to choose a method and CL scenario to run. We did a single run of each method (due to our more limited hardware) while the researchers performed several runs and averaged the results , giving a slight margin in the results - with some up to 10%.

After verifying the results, came the time to implement our own versions of each method. Initially, the entire code for our implementation was in a single file - making it difficult to navigate and separate the different method's function. To solve this we split the Implementation into multiple files:
- A file for each method - functions relevant to it
- A file containing general functions used by multiple methods (dataset loading, splitting and testing the models)
- A file for interfacing with the program - choosing what method + scenario to test
- Files to handle the organization of the results into graphs

Throughout the project, we used Github to upload and manage our code, display our results, and document the process. It was a great way to stay organized and track our progress. For a future project, I would use Github more extensively as our use was quite basic and the functionality offered is much more in depth.

This project was a new experience for me, as I haven't worked with AI to that extent. I learned how to better my instructions - describing as clearly as I can what I want to achieve and important factors I wanted considered in the implementation.  There was a bit of a learning curve, as sometimes the choices the AI made didn't align we ours, or the code it generated had some issues, but in the end we managed to direct it to do what we asked and get a working project.

An important decision we made for the project as adapting the scope. Our paper had a lot of methods compared (as it was an overview) so we decided to focus on a few methods to test across the 3 CL scenarios, as well as choosing one dataset out of the 2 used in the paper. Adapting the scope to better fit our project made sure we stayed realistic and finished it in time.

Another challenge we had was the material of the paper - I didn't know much about catastrophic forgetting or the methods used to combat it, the paper gave us the opportunity to learn more about a subject still being researched, and even try our hand in solving the problem using the tools and knowledge we gathered.

In conclusion, the project was a great opportunity for me to both learn how to use AI in projects, and research a problem AI is facing (CF) to understand existing solutions and their shortcomings.  I now know better the difficultly of solving the catastrophic forgetting problem and I'm interested to see what new solutions might be invented next.
